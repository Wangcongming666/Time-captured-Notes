## 5. 设计阶段必须解决的风险

| 风险 | 架构必须回答的问题 | 所涉视图 |
|---|---|---|
| 数据提交成功但消息未发出 | 事务提交与可靠补发如何衔接？何时重试，谁接管未完成投递？ | 数据、运行、开发 |
| 消费者重复处理 | 去重记录是否与业务副作用同事务？重放和保留期如何协调？ | 数据、运行 |
| 两名审核员同时决策 | 审核目标版本、状态和操作者如何校验？冲突如何反馈？ | 逻辑、数据、运行 |
| 下架内容仍留在缓存或图片链接 | 列表、详情、媒体授权怎样统一重新验证可见性？ | 逻辑、数据、物理 |
| 公开实践反馈绕过治理 | 反馈及其媒体如何审核、举报、撤回和随原笔记失效？ | 逻辑、数据、运行 |
| 点赞/收藏重复与统计负数 | 关系事实的唯一性、取消语义、计数口径及对账如何定义？ | 数据、运行 |
| MQ暂时不可用 | 写操作是否可受理？积压如何限界，恢复后如何验证不丢不重？ | 数据、运行、物理 |
| Redis不可用 | 哪些读取可降级、哪些安全操作须拒绝？如何防止数据库被打满？ | 运行、物理 |
| 推荐分页漂移 | 候选排序、游标、刷新、隐藏和偏好改变时如何避免重复或泄露？ | 逻辑、数据、运行 |
| 文档与代码失配 | 模块事实由谁维护？依赖规则如何自动校验？ | 开发、逻辑、五视图追溯 |

这些是待设计的问题清单，不表示已选择具体实现。最终ADR须写出实际决策、备选和验证条件。
