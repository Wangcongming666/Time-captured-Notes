# 核对架构与实现

## 1. 适用场景
在拾光笔记增加或修改HTTP接口、同步OpenAPI、核对文档与源码分层或准备课程交付时使用。扫描真实路由并输出覆盖率清单，发现漂移即失败。

## 2. 前置条件
仓库03-源码/backend源码存在；Python3安装PyYAML；源码OpenAPI是实施后的权威契约，设计目录保留审定设计版本。

## 3. 执行步骤
1. 运行 scripts/sync.py --root . --output docs/接口一致性.json。
2. 缺失操作要补03-源码/docs/api/openapi.yaml，不能静默忽略。
3. 更新01-架构设计文档/实施差异说明.md，保留原设计历史。
4. 重新执行直到无缺失和幽灵接口，再运行真实HTTP样本校验。

## 4. 强制约束
接口覆盖率按HTTP方法+标准化路径计算，路径参数名差异不算新接口。统一ApiResponse(code,message,data,traceId)，ID字符串，UTC ISO8601。额外字段须更新DTO契约，不能关闭全部additionalProperties约束掩盖漂移。

## 5. 输出物清单
接口一致性JSON（所有实现/契约路由、缺失、覆盖率）、实施差异说明。

## 6. 自检清单
退出0才表示路由完全一致；扫描器不验证响应体，必须另做HTTP契约测试；文档不将查询时刻伪称汇总水位。

## 7. 常见错误与反例
错误：复制旧OpenAPI后仍写“设计未实现”。正确：以真实源码路由核对并记录新增管理查询接口。
